# Quickstart

These steps start the Phase 0 system on your machine: Postgres, the API, the worker, and the web page.

## What you need

- Docker, with Compose v2
- Nothing else. The images build the Python and Node toolchains themselves

For working on the code without Docker, you also need Python 3.12, [uv](https://docs.astral.sh/uv/), Node.js 22, and pnpm 10.21.0. The frontend `package.json` pins that pnpm release. Corepack will use it when `packageManager` is set.

## Start the stack

From the repository root:

```powershell
docker compose -f deploy/docker-compose.yml up --build
```

Then open:

- Web: <http://localhost:3000>
- API health: <http://localhost:8000/health>
- API docs (generated by FastAPI): <http://localhost:8000/docs>

`/health` returns HTTP 200 when the API can run `SELECT 1` against Postgres. The page at port 3000 reads that endpoint from the browser and shows "API ready".

Copy `.env.example` to `.env` only when you want to override a default. Compose runs without that file. See [configuration](../09-operations/configuration.md).

## Work on the backend

```powershell
uv sync --directory backend --group dev
uv run --directory backend pytest
uv run --directory backend uvicorn honest_practice.api.app:app --reload --port 8000
```

Postgres still has to be running. The compose file can start it on its own:

```powershell
docker compose -f deploy/docker-compose.yml up postgres
```

The default database URL points at `localhost:5432` with user, password, and database all set to `honest_practice`.

## Work on the frontend

```powershell
pnpm install --dir frontend
pnpm --dir frontend dev
```

The dev server uses `http://localhost:8000` unless `NEXT_PUBLIC_API_URL` is set. That variable is read when the production image is built, not at request time.

## Build the docs

```powershell
uv run --directory backend mkdocs build --strict --config-file ../mkdocs.yml
```

The site is written to `site/`. To read it while editing:

```powershell
uv run --directory backend mkdocs serve --config-file ../mkdocs.yml
```

`mkdocs` is a backend development dependency, which is why the command runs through `uv` in `backend/` while the config file stays at the repository root.
